## What exists
- `server/orchestration/engine-registry.ts` — manifest of platform engines with domain/geography-grain/PII tags.
- `server/orchestration/conductor.ts` — `getOrchestratedIntelligence(geo, {engines?, domains?})` calls relevant engines in parallel, returns provenance-tagged bundle.
- Wired into `queryRAG` (both non-streaming and streaming paths) in `server/rag-engine.ts` — geography auto-detected from a ZIP mentioned in the user's query.
- **24 of 25 registered engines are now wired in-process** (`IN_PROCESS_ENGINE_IDS` in `conductor.ts`): chainweb-engine, gis-engine, equity, benefits, corridor-chainweb, scorecard, corridor-story, farmworker-iti, reentry, resident-journey, regional-briefing, rural-health, rural-workforce, rural-housing, neighborhood, safe-passage, farm-cooperative, farm-profitability, foster-youth-agency (prior session), plus this session's final batch: **workforce** (aggregate COUNT-by-readinessLevel over `workforceAssessments`, joined userId→participantProfiles.userId→zipCode→zctaCountyMap→countyFips), **justice** (aggregate COUNT-by-status over `justiceReferrals`, same join chain; `supervisionCompliance` deliberately not joined — no independent geography path, no added safe signal), **trade-sims** (aggregate COUNT-by-status over `tradeSimsLessonProgress` only — `tradeSimsSandboxProjects` excluded, its canvasState/name are free-text and unsafe to touch even for a count), **clinical** (aggregate COUNT-by-`rnrRiskLevel` ONLY, joined participantId→participantProfiles.id→zipCode→zctaCountyMap→countyFips — never rnrTotalScore/phq9*/pcl5*/referrals/*Responses), **rural-connectivity** (PARTIAL: `getServiceDesertScore(stateFips, countyFips)` is genuinely callable in-process since its Census ACS call never needed lat/lng despite the function signature; FCC broadband/cell-coverage sub-features remain unwired — they need real lat/lng, `GeographyRef` doesn't carry it, and there's no county-centroid table in this repo to derive one without fabricating a point).
- **college-access-ai is the only engine NOT in `IN_PROCESS_ENGINE_IDS`, and it's by design, not a schema blocker**: no backing geography-indexed dataset exists (it's a live per-request AI advisor), so auto-firing it inside domain-wide orchestration bundles would create unbounded paid-LLM-call exposure — an AI-spend/DoS profile distinct from every other engine (see threat_model.md). Registry keeps `touchesPII: true` on it so the PII wall also excludes it as a second layer. Call its routes directly with a specific student question for real use instead.
- Small-cell suppression helper `suppressSmallCells()` (floor `MIN_AGGREGATE_CELL = 5`) added this session in `conductor.ts` and applied to all 4 new count-aggregate branches (workforce/justice/trade-sims/clinical); clinical additionally guards on total-below-floor.
- **Pattern for wiring a PII-table engine as aggregate-safe**: join down to just the geography key + the one non-identifying field being counted/grouped, filter to the target county/state, GROUP BY + COUNT — never select(`*`) or any name/contact/notes column. Document in the registry `notes` field exactly which columns the aggregate touches and which raw sensitive columns exist on the underlying table but are never selected, so a future edit that "helpfully" widens the select doesn't silently break the PII wall (registry `touchesPII: false` is a claim about the *query path*, not the *table* — see Safety note below).
- **ZIP→county nationwide resolution is solved.** `zctaCountyMap` DB table loaded from the Census ZCTA-County relationship file via `scripts/load-zcta-county.ts` (idempotent). `server/geo/zip-county-resolver.ts` exposes `resolveZipBestEffort()`: DB lookup first, static fallback table second.
- Instrument picker has a real UI: `client/src/pages/ecosystem-ai.tsx` domain-toggle chips pass `domains` to `POST /api/ecosystem-ai/stream`.
- Pattern for adding a new DB-backed engine: check the table has a `countyFips`/`zipCode`/`stateCode` column (or a join path to one) in `shared/schema.ts` before wiring — if there is none anywhere in the join graph, that's a real schema blocker, not a quick win; report it as blocked rather than fabricating a join. (This session's re-check found the 5 previously "blocked" engines actually DID have a join path via `participantProfiles` — the earlier "no geography column" conclusion was about the direct table only, not the full join graph. Always trace the full join graph, not just the immediate table, before declaring a schema blocker.)

## Safety note discovered while wiring engines
`touchesPII: false` on an ENGINE_REGISTRY entry is a per-*engine-query-path* label, not a per-*table* guarantee. Several engines (benefits, farm-cooperative, farm-profitability, foster-youth-agency, workforce, justice, trade-sims, clinical) sit on top of tables that are genuinely PII-bearing at the row level (name/phone/email/case-ID/mental-health-flag/skills/notes columns) — the engine is only wall-safe because the specific conductor branch selects nothing but a geography key + one non-identifying field for a COUNT/GROUP BY, with small-cell suppression. Always open the actual table definition in `shared/schema.ts` (or `clinical-schema.ts`) and check for identifying columns before wiring or widening a new query, regardless of what the registry currently says.

## Hard constraints discovered (do not re-attempt without new info)
- ~~No free ZIP-only geocoding API exists~~ — resolved, see above.
- FCC broadband-availability and cell-coverage lookups inside rural-connectivity need real lat/lng; `GeographyRef` doesn't carry coordinates and no county-centroid table exists. Adding one would require either a new small centroid dataset or an explicit decision to approximate — don't fabricate a point silently.
- college-access-ai has no backing dataset and is excluded by design (AI-spend/DoS), not a schema gap — re-wiring it as an auto-included orchestration engine would require a real cost/rate-limit control first, not just a code change.

## Why this matters
The project's whole culture is anti-fabrication (Iron Rule #2, #10, #11) — an orchestration/audit claim that isn't actually backed by a working code path or a real test run is a project-level trust violation here, not just a bug.

## How to apply
Before extending the Conductor to a new engine, check `IN_PROCESS_ENGINE_IDS` in `conductor.ts` — if the target engine isn't in that list, either add a genuine function-call path or an internal-fetch-to-its-own-route path; don't fake a result. Before declaring a new engine "blocked," trace the FULL join graph in `shared/schema.ts`, not just the immediate table's own columns.
