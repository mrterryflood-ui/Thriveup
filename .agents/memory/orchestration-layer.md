## What exists
- `server/orchestration/engine-registry.ts` — manifest of platform engines with domain/geography-grain/PII tags.
- `server/orchestration/conductor.ts` — `getOrchestratedIntelligence(geo, {engines?, domains?})` calls relevant engines in parallel, returns provenance-tagged bundle.
- Wired into `queryRAG` (both non-streaming and streaming paths) in `server/rag-engine.ts` — geography auto-detected from a ZIP mentioned in the user's query.
- 10 engines now wired into the in-process Conductor (`IN_PROCESS_ENGINE_IDS` in `conductor.ts`): chainweb-engine, gis-engine, equity, benefits, corridor-chainweb (read-only accessor `getLastChainWebRun()` — never triggers a live Census/FBI-hitting run), scorecard, corridor-story (Waco/Austin I-35 narrative — hardcoded to McLennan 48309 / Travis 48453 only, returns explicit out-of-scope error for any other county; verified via direct in-process call returning real ACS/CDC-sourced data), **farmworker-iti** (aggregate-only COUNT-by-workerType over `farmworkerItiEnrollments`, matched on `stateFips`+`countyFips`), **reentry** (aggregate-only COUNT-by-phase, joins `reentryPlans`→`participantProfiles.zipCode`→`zctaCountyMap`→target county; selects ONLY phase + zip, never name/notes/goals), **resident-journey** (aggregate-only COUNT-by-eventDomain over `residentJourneyEvents`, matched directly on `countyAtEvent` — that column already stores full 5-digit FIPS, no join needed; verified live with real data: 10 events across 5 domains for Travis County 48453). All three new PII-table engines verified in-process; farmworker-iti/reentry return honest zero-count when no rows exist rather than fabricating data.
- **Pattern for wiring a PII-table engine as aggregate-safe**: join down to just the geography key + the one non-identifying field being counted/grouped, filter to the target county, GROUP BY + COUNT — never select(`*`) or any name/contact/notes column. Document in the registry `notes` field exactly which columns the aggregate touches, so a future edit that "helpfully" widens the select doesn't silently break the PII wall (registry `touchesPII: false` is a claim about the *query*, not the *table* — see Safety note below).
- **ZIP→county nationwide resolution is now solved** (previously a hard blocker — see below). `zctaCountyMap` DB table loaded from the Census ZCTA-County relationship file (33,120 ZIP rows, best-population-share county per ZIP) via `scripts/load-zcta-county.ts` (idempotent, re-runnable). `server/geo/zip-county-resolver.ts` exposes `resolveZipBestEffort()`: DB lookup first, falls back to the old static 5-county/state-only range table (`shared/nationwide/zip-resolver.ts`) only if the DB has no row or the query throws. `extractGeographyFromQuery` in `server/rag-engine.ts` is now async and uses this resolver — any US ZIP mentioned in an ecosystem-AI query now resolves to its real county nationwide, not just a state guess outside the seeded 5-county region. Verified: 90210 now resolves to CA county 06037 (LA County) via DB, not just "CA state" from the static fallback.
- Remaining route-only engines split into two real buckets, not just "not done yet": (a) live-external-API engines with no backing DB table (rural-health/-housing/-connectivity, neighborhood, regional-briefing) — wiring these in-process means either a refactor to a callable function or accepting multi-second external HTTP latency inside the Conductor's parallel call, not a quick win; (b) PII-bearing engines with genuinely no county-aggregate path yet (workforce, justice, clinical, trade-sims, foster-youth-agency, safe-passage). `justiceReferrals`/`workforceAssessments` have NO zip/county column at all — the new ZCTA table can't help them; that needs a schema change, not a resolver. `safe-passage-routes.ts` is in-memory-array only, not a persisted DB table — not wireable as a durable data source at all today. (`resident-journey` was moved OUT of this bucket — it's now wired in-process, see above.)
- Instrument picker has a real (minimal) UI: `client/src/pages/ecosystem-ai.tsx` has domain-toggle chips above the chat input that pass `domains` to `POST /api/ecosystem-ai/stream`; verified end-to-end with curl (domains filter accepted, sourced response returned).
- Pattern for adding a new DB-backed engine: check the table has a `countyFips`/`zipCode` column (or a join path to one, e.g. via `zctaCountyMap`) in `shared/schema.ts` before wiring — PII-bearing engines with genuinely no geography column anywhere in their join graph (workforce, justice/`justiceReferrals`, clinical) don't have a "safe aggregate by county" path buildable without a schema change; don't fake it.

## Safety note discovered while wiring engines
`touchesPII: false` on an ENGINE_REGISTRY entry is a per-*engine* label, not a per-*table* guarantee. The `benefits` engine, for example, spans multiple tables — `benefitsEnrollmentData` (safe, county aggregate, no PII columns) but also `benefitsApplications`/`benefitsScreenings` (applicant name/phone/email, household composition). Conductor only ever queries `benefitsEnrollmentData` for this engine — do NOT extend it to the other benefits tables without re-classifying them, even though the registry entry says `touchesPII: false` at the engine level. Always open the actual table definition in `shared/schema.ts` and check for name/phone/email/address columns before wiring a new query, regardless of what the registry says.

## Hard constraints discovered (do not re-attempt without new info)
- ~~No free ZIP-only geocoding API exists~~ — **resolved**: bulk-loaded the Census ZCTA relationship file into `zctaCountyMap` once (see above); that was always the correct fix, live per-request geocoding APIs genuinely don't support bare-ZIP lookup.
- **Most engines are still route-only, not in-process callable.** 8 of 24 registered engines are wired (see above); the remaining ~16 (rural-*, workforce, justice, regional-briefing, neighborhood, safe-passage, reentry, clinical, trade-sims, college-access-ai, foster-youth-agency, farm-*, resident-journey) are listed in orchestration output as explicitly "not yet wired" rather than silently skipped — do not make them silently disappear.

## Why this matters
The project's whole culture is anti-fabrication (Iron Rule #2, #10, #11) — an orchestration/audit claim that isn't actually backed by a working code path or a real test run is a project-level trust violation here, not just a bug.

## How to apply
Before extending the Conductor to a new engine, check `IN_PROCESS_ENGINE_IDS` in `conductor.ts` — if the target engine isn't in that list, either add a genuine function-call path or an internal-fetch-to-its-own-route path; don't fake a result.
