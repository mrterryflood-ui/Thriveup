# Alpha Omega — 2026-10-03 — Focused platform experience

## Alpha
- End-state: user approved all three entry methods, distinct workspaces and evidence-constrained inference; "Great site information wise. Bad experience overall."
- In-state evidence: App.tsx renders the broad sidebar, five cross-sector tabs and floating helpers; iframe branch removes navigation. Landing is a long information page; hub exposes seven gateways and nine tools. Sidebar and command palette already share access flags.
- Hypotheses: audience mixing; capability-first names; competing entry mechanisms. These explain observed structure, not measured user outcomes.
- Authority/boundaries: preserve existing URLs, APIs, permissions, personal journey data and information content. No database changes, credential handling, external mutation, repository pull, or publishing.
- Environmental scan: residents need public access without accounts; practitioners require authenticated authority; funders need public evidence distinct from internal grant operations; community leaders need scoped source-aware analysis. Mobile and restricted storage must work. AI is not required for navigation.
- Reuse: existing tools, route gates, search catalog, authentication, logo, components. Extend: app-wide shell and entry routing. New: small typed task/workspace/routing catalog because existing sector lists mix audiences. Not touching: clinical/eligibility logic, referral writes, grant scoring, partner APIs.
- Plan backward: verify all entry paths converge on registered routes and shared workspace context; implement catalog/persistence first; design focused home and workspace pages; integrate sidebar, search and mobile shell; validate typecheck, routing tests, browser desktop/mobile and six-domain audit.
- Stakeholder red-team: public tools stay public; workspace preference grants no authority; no personal intake enters navigation URLs/storage/logs; unknown/multiple matches ask the user rather than select; full information remains discoverable; staff operations remain explicitly accessible to eligible users.
- Independent pre-build angle: design worker reviews functional brief against user needs before implementing UI; executable tests challenge ambiguous routing and gate parity.
- Unknowns: improvement in real-user burden requires post-release measurement, not inferred from screenshots. This build changes platform-wide discovery/navigation, not every specialist tool's internal workflow.

## Omega
- Changed: focused home and four workspace perspectives; task catalog and optional local guide; scoped sidebar, command palette and three mobile tabs; explicit workspace chooser; full directory union of existing sidebar, command-palette and curated destinations; original information preserved at /platform-overview and legacy hub at /hub/legacy.
- Why: provide distinct task/workspace entry methods without requiring personal intake or discarding useful specialist tools. Preference is display context, never entitlement.
- Boundary correction from audit: case-review API had no staff guard despite practitioner discovery metadata. Reused DB-backed canonical staff authorization, aligned CHW/case-review UI gates and personal journey/document/appointment sign-in gates, and disclosed the case-risk view as a demonstration rather than a complete case-management system. No schema, credential or real-user data changes.
- Runtime/privacy: guide text is local-only and not stored or transmitted; only a workspace ID is session-stored. Restricted storage fails visibly without crashing. Viewer role resolution is shared once per shell rather than duplicated per task card. Root navigation is network-first; private API/page content is not placed in static cache; failed cache writes do not discard a healthy network response.
- Narrow proof: zero TypeScript errors; changed frontend files lint without warnings; production build exits 0; 11 routing/catalog tests, 10 staff authorization tests, 5 service-worker tests pass. Staff tests use mocked persisted-role lookup, not real staff sessions; anonymous live case-review request returns 401. Permission sync validates 19 restricted paths; sidebar route gate covers 277 URLs; public two-click graph reaches 219 routes.
- Independent proof: six read-only audit domains examined contracts, runtime, navigation, storage, UX and symmetry. Findings were reconciled via focused fixes and narrow guards. - Browser residual: ordinary direct iframe rendering was blocked by inherited CSP frame-ancestors 'none' and X-Frame-Options DENY before application execution.
