## Scope

Harden the additive Studio manifest contract and its public and organization runtime paths without deploying or changing production data.

## Evidence

- Public runtime fields are constrained to declared select or checkbox controls, avoiding free text and exact identifying dates.
- Public metadata rejects literal email addresses, phone numbers, and government identifiers.
- Organization records require a declared organization/aggregate submit action, have per-manifest bounded retention, and return no more than the newest 100 records.
- Authenticated organization-only modules have a protected runtime manifest endpoint; public discovery remains public-only.
- Runtime mutations use in-flight guards, refresh after organization writes, and require confirmation before deletion.

## Verification

- Focused Studio manifest and follow-up checks are run after changes.
- Strict TypeScript, preflight, workflow restart, logs, and a live preview remain required before closure.

## Limits

- No deployment or production-data operation is authorized.
- Browser authentication flows require a test session; anonymous route proof cannot establish organization ownership behavior.
