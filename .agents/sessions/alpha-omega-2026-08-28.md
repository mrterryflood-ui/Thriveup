# Alpha Omega — 2026-08-28 — Community Events archive concurrency
## Alpha
- End-state: Archived Community Events records must remain permanently read-only when an archive transition races an event, attendance, need, action, or story mutation.
- In-state evidence: Write routes checked archive status before their transactions. A concurrent archive could therefore win after that check and leave an in-flight child write able to commit. The focused verifier covered only sequential post-archive rejection.
- Authority/boundaries: `server/nonprofit-events-routes.ts` owns route authorization and mutation transactions; PostgreSQL row locking owns serialization. This change does not add attendee identities, contact data, integrations, or production schema/data changes.
- Plan and acceptance proofs: Lock the organization-scoped parent event row inside every mutation transaction; re-read archive status under the lock; return `409` for archived writes; recheck archive state transactionally and audit only successful transitions; add a deterministic waiting-transaction proof; run focused gates, preflight, memory health, and audit review.
- Unknowns/deferred decisions: The preview harness could not reliably place two HTTP requests into separate blocked database sessions; the regression therefore uses two direct PostgreSQL transactions for deterministic lock ordering, plus live endpoint checks for normal archive and post-archive rejection.
## Omega
- Diff scrimmage: Event updates, attendance, need create/update/delete, action create/update, and story create/update now lock the parent event row inside their write transaction. Child update/delete paths lock the child first and then the parent; no route acquires those locks in reverse order. Archive locks the parent, rechecks status, and records its audit entry within the same transaction.
- Proofs and gates: Live nonprofit-event verification passed, including the waiting mutation observing `archived` and the live endpoint returning `409` after archive. A publish-blocking membership composite-key repair was applied at startup; a rollback-only replay of its exact failed foreign-key statement now succeeds. TypeScript, diff-whitespace, preflight, and memory health checks passed.
- Independent angle: Manual six-domain adversarial review covered API contracts, runtime/concurrency, UI/navigation, storage, UX/performance, and full-stack congruence. Architect subagent review was unavailable in the selected free runtime and is recorded as a capability limitation, not a fabricated pass.
- Outcome: The archive race is guarded by transactional parent-row serialization and archived-state revalidation.
- Residuals and reusable guard: Keep the event archive concurrency regression in the focused verifier and preserve the existing urgent residual for broader authorization/event-audit hardening outside this task.
