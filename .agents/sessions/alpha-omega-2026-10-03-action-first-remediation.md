# Alpha Omega — Action-first utilization remediation

## Alpha / environmental scan
- User-authorized end-state: remediate, execute and sustain a platform people can actually use, rather than a box of knowledge they do not know how to open.
- Observed baseline: the 390×844 homepage screenshot shows a large introductory block and no actual task choices in the first viewport. Desktop mixes personal tasks with professional tasks; optional guidance is far down the page. Existing workspace task cards already carry actionable nextStep instructions, but large introductions put them below the phone fold.
- Three mechanisms considered: introductory content displaces actions; mixed audiences force classification before action; destination/context transitions and missing behavioral guards allow navigation to remain technically correct but difficult to use. The first two are directly visible; measured utilization remains unknown.
- Existing assets: shared/workspace-catalog.ts owns routes, task instructions and access rules; WorkspaceProvider owns display context; GuidedStart gives local-only clarification with explicit confirmation; full directory and original platform overview remain accessible.
- Authority: implement in development. Preserve URLs, resource contracts, source disclosures, staff authorization, all four stakeholder entrances, useful specialist content and personal data. No credential changes, repository pull/push, publishing, external-service mutations, new AI calls or schema changes.
- Stakeholders: residents need immediate public actions without accounts; organizations need distinct operational/funding entrances; funders need evidence rather than grant operations; community leaders need source-aware analytical work. Workspace choice must never grant authority. Mobile, keyboard, zoom and restricted-storage users cannot be excluded.

## Backward plan / MAP-GAP
1. First-viewport startability: three direct resident tasks plus an immediately reachable optional guide; professional perspectives distinct and discoverable. No intermediary marketing/choice page before existing workflows.
2. Activation continuity: compact workspace task introductions and task-specific arrival guidance with explicit next step, back/change path and truthful scope; no completion claim from a route visit.
3. Sustainment: deterministic route/access parity and Playwright guards for 360×640/390×844 startability, direct public destinations, optional local guidance, role gates and workspace task reachability. Integrate with existing validation rather than creating a parallel service.
4. Verify zero-error TypeScript, lint, build, relevant navigation tests, workflow startup/logs, one independent changed-journey browser pass and six scoped read-only audits.
- Independent pre-build angle: design specialist examines this brief against live source and supplies presentation; main agent owns shared behavior and sustainment contracts.
- Stop condition: a phone visitor can see and activate actual starting choices without scrolling; destinations retain instructions and permissions; checks guard the repaired failure class. Actual adoption/outcomes require observed use and are not inferred from tests.
