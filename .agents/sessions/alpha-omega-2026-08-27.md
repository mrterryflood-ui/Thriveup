# Alpha Omega — 2026-08-27 — Community Opportunity Mirror
## Alpha
- End-state: Nationwide equity-loss batches must resolve Connecticut's nine Census planning-region county equivalents from CDC USALEEP's legacy tract data without name matching, geographic mixing, or fabricated values. The public summary must distinguish analytical source readiness from service deployment and show states, D.C., territories, present records, usable records, source-unavailable records, and missing records clearly.
- In-state evidence: The current completed batch includes all nine Connecticut planning-region FIPS rows but suppresses each as `source_coverage_gap`; both manual and scheduled paths use the same display-name lookup. CDC USALEEP exposes 829 legacy Connecticut tract rows across its eight former counties. The Census Bureau's published files provide (1) 183 legacy-county/town-to-planning-region relations, (2) 906 town-to-2022-tract relations, and (3) 1,337 Connecticut 2020-to-2010 tract relations. Chaining their stable identifiers resolves 821 source tracts to exactly one modern planning-region FIPS, covers every region, and identifies eight boundary-spanning tracts.
- Authority/boundaries: CDC USALEEP remains the authoritative health source; Census relationship files are the geographic authority. A source tract with more than one planning-region target is not an observed value for either target and must remain excluded. The existing suppression engine remains the authority when source data cannot be resolved. This work changes no source data, public deployment claim, or health methodology.
- Plan and acceptance proofs: Build one FIPS-based resolver in the USALEEP source module; have both batch paths call it; validate official input shape and report crosswalk unavailability explicitly. Add method documentation and focused fixtures for unique, boundary-spanning, and unavailable tracts. Extend summary responses from the canonical jurisdiction universe and RUCC county universe. Scope the nationwide verifier to the selected completed batch and fail when live legacy source data coincides with a statewide `source_coverage_gap`. Prove source alignment, batch/UI/API contracts, zero-error typecheck, relevant gates, browser rendering, audit, and independent review.
- Unknowns/deferred decisions: The eight tracts that cross planning-region boundaries cannot be allocated without a source-supported sub-tract life-expectancy rule; they remain excluded. The change validates development data and sources only; no claim about a production deployment is made.
## Omega
- Diff scrimmage: Replaced Connecticut's legacy display-name join with the Census identifier chain and removed every direct caller's ability to make a Connecticut source-name lookup. The review also found and corrected stale client-request cleanup, partial-jurisdiction labeling, undisclosed reference failures, synthetic zero-growth peer classifications, and partial batches marked completed.
- Proofs and gates: Zero-error TypeScript compilation; 35 access-model checks; five focused Connecticut/coverage tests; nine live nationwide checks; and 58 nationwide API checks passed. The selected completed development batch contains 3,233 present county-equivalent records, 2,721 usable records, zero failed computations, and all nine Connecticut Planning Regions resolve without a source-coverage-gap row. The first platform-wide completion run had two unrelated youth-mode response waits time out under concurrent validation; its serialized, lock-protected rerun passed all five youth-mode flows without a code change. A direct port-5000 capture of `/equity-loss/national` is saved at `screenshots/equity-loss-national-final.jpg`.
- Independent angle: Six-domain adversarial audit rerun on the final exact revision returned CLEAN in every domain. The independent architecture reviewer approved the final revision with no blocker.
- Outcome: Connecticut's updated Planning Regions are resolved only by their authoritative Census relationship chain; boundary-spanning source tracts remain excluded rather than allocated. Manual, scheduled, direct public, Civic Signal, and peer-benchmark paths share the FIPS-aware resolver. The public report and API distinguish analytical jurisdiction/record coverage from service deployment, and permanent checks prevent a statewide Connecticut source gap or a partial-jurisdiction mislabel.
- Residuals and reusable guard: The Replit development proxy returned HTTP 502 after three real-browser attempts even though port 5000 is bound to `0.0.0.0`, locally returns HTTP 200, and the configured mapping is 5000→5000. This blocks proxy-mediated interaction proof only; it is recorded as a monitored platform-routing residual and no production claim is made. The permanent guard runs the FIPS alignment/direct-lookup fixture and partial-jurisdiction coverage test through `access-model-guards`.
