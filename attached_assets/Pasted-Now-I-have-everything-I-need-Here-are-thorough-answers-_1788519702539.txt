## 1. Does ThriveUp expose an API to receive data from ChildCORE?

**Yes — it's live and production-ready.**

ThriveUp has a fully-documented Partner API at `/api/partner/v1/` that was built specifically for external platform integration. Here's the concrete spec:

**Authentication:**
Every request requires a scoped API key in the header:
```
X-Partner-Key: tcaf_<hex>
```
(Also accepted as `Authorization: Bearer tcaf_<hex>`). Keys are provisioned by the TCAF admin team via the Ops Center → Partner API tab. A ChildCORE-specific key would be created there with exactly the scopes needed — nothing more. The key format always begins with `tcaf_` so it's unambiguous at a glance.

**The inbound data endpoint — how ChildCORE pushes to ThriveUp:**
```
POST /api/partner/v1/push
X-Partner-Key: tcaf_<your-key>
Content-Type: application/json

{
  "dataType": "metric",
  "payload": { ... county-keyed aggregates ... }
}
```
Accepted `dataType` values: `"metric"`, `"intervention"`, `"grant_outcome"`, `"content"`, `"event"`, `"insight"`, `"update"`, `"referral"`, `"alert"`. For childcare data, `"metric"` and `"intervention"` are the right types.

The endpoint validates known schemas, corrects out-of-range fields, audit-logs every inbound call, and returns a receipt including an ID and timestamp. If any field is invalid it's corrected rather than rejected, and the response tells you exactly what changed — so ChildCORE always knows what ThriveUp accepted.

**The heartbeat endpoint:**
```
POST /api/partner/v1/heartbeat
```
Registers ChildCORE's platform health status in ThriveUp's 29-platform ecosystem (the pinger checks all platforms every 60 minutes). This is how ThriveUp knows if ChildCORE is ONLINE/OFFLINE without polling it constantly.

**Self-documenting:** `GET /api/partner/v1/docs` (no auth required) returns the full API contract as JSON — every endpoint, expected shape, scope required, and example payloads. The ChildCORE builder can fetch that and have the entire spec programmatically.

## 2. What exact aggregates does ThriveUp want from ChildCORE?

Here's what would be most valuable and what ThriveUp's existing engines already know how to consume:

**Core county-keyed metrics** (county_fips is the join key for the equity-loss engine and community brief):

| Field | Why ThriveUp needs it |
|---|---|
| `total_providers` | Feeds gap analysis baseline |
| `total_licensed_capacity` | Direct input to slot-gap calculation |
| `estimated_demand` | Needed to compute coverage rate (# children 0–5 in county) |
| `slot_gap` (capacity minus demand) | The headline number for funder reports |
| `coverage_rate` (capacity / demand, 0–1) | Equity-loss divergence frame: how far below 100% coverage |
| `subsidized_providers_pct` | % accepting CCDF / childcare subsidy vouchers — critical for equity framing |
| `nonstandard_hours_pct` | % offering care outside 7am–6pm — key for workforce-development families |
| `trs_high_quality_pct` | % at TRS Star 3+ — feeds quality-improvement grant eligibility |
| `trs_rated_pct` | % that have any rating at all |
| `suppressed_children_served` | Count of children served, floor-5 suppressed per YHSI doctrine |
| `as_of_date` | When the data was last refreshed from HHSC |

**Suppression rule:** Any cell where the count < 5 should be sent as `null` with a `suppressed: true` flag. ThriveUp enforces this same floor on all youth and community outcome data internally (YHSI doctrine) and will reject or null any sub-5 cell that arrives without the flag.

**Push format example:**
```json
POST /api/partner/v1/push
{
  "dataType": "metric",
  "payload": {
    "source": "ChildCORE",
    "county_fips": "48491",
    "county_name": "WILLIAMSON",
    "state": "TX",
    "as_of_date": "2026-09-04",
    "total_providers": 541,
    "total_licensed_capacity": 45032,
    "estimated_demand": 72000,
    "slot_gap": 26968,
    "coverage_rate": 0.626,
    "subsidized_providers_pct": 0.43,
    "nonstandard_hours_pct": 0.12,
    "trs_high_quality_pct": 0,
    "trs_rated_pct": 0,
    "suppressed_children_served": null,
    "suppressed_children_served_flag": true,
    "suppression_reason": "cell_below_floor_5"
  }
}
```

ThriveUp would then surface this in the Community Brief for Williamson County ZIP codes, the equity-loss divergence analysis for WSRCA's 9-county service area, and the grant targeting logic (grants for childcare gap / quality improvement / workforce).

## 3. Does data flow the other way — ThriveUp → ChildCORE?

**Yes, and this is the more valuable half of the integration for ChildCORE.**

ThriveUp's outbound API gives ChildCORE things it would otherwise have to build from scratch:

### Grant intelligence (the most immediately useful)
```
GET /api/partner/v1/community-story?location=78664&orgName=ChildCORE
X-Partner-Key: tcaf_<key>
```
Returns a complete community story pack: Census-grounded demographic context, SDOH scores, grant opportunities matched to the geography, and a shareable narrative suitable for embedding in a grant proposal or stakeholder report. Rate-limited to 10/hour per key.

ThriveUp currently tracks 2,100+ active grants from SAM.gov, Grants.gov, USASpending, and SAMHSA — many tagged to childcare, early education, workforce development, and CCDF quality improvement. ChildCORE pulling these rather than building its own grant scanner saves months of work and stays current automatically.

### Community brief (Census + SDOH data, no build required)
```
GET /api/partner/v1/community-brief?location=<zip>&populationSize=10000&timeHorizon=25
```
Returns poverty rate, median household income, unemployment, housing burden, health coverage gaps, HDI, and scenario projections — all sourced directly from ACS5 Census and USALEEP. This is the data ChildCORE would otherwise need its own Census API key and pipeline for. ThriveUp's pipeline is already live for all 50 states. Rate: 20/hour per key.

### Benefits programs catalog
```
GET /api/partner/v1/benefits
```
The TCAF benefits program database — CCDF subsidy, CHIP, WIC, SNAP, TANF, childcare tax credits, and workforce training grants. ChildCORE can use this to show families what financial assistance is available for the providers in their area.

### Webhook events (event-driven instead of polling)
```
POST /api/partner/v1/webhooks
{
  "url": "https://childcore.example.com/webhooks/thrive",
  "events": ["grant.opportunity.new", "referral.created", "referral.outcome"]
}
```
ThriveUp fires these in real-time. ChildCORE can receive a webhook when a new childcare-relevant grant opens, rather than polling.

### Subscribe to community brief updates
```
POST /api/partner/v1/community-brief/subscribe
{
  "location": "78664",
  "webhookUrl": "https://childcore.example.com/webhooks/brief",
  "frequency": "weekly"
}
```
ThriveUp pushes a fresh community brief to ChildCORE on schedule, so ChildCORE's data stays current without any cron job on their side.

**So the integration contract is genuinely bidirectional:**
- **ChildCORE → ThriveUp:** Provider capacity, gap metrics, and childcare outcomes (via `/api/partner/v1/push`)
- **ThriveUp → ChildCORE:** Grant catalog, community briefs, benefits programs, and real-time webhook events

## 4. What does ThriveUp do, in plain terms?

The best one-paragraph description from the inside:

**ThriveUp is a national community-infrastructure platform that does three distinct things simultaneously, and the value is in how they connect:** (1) It connects people — residents, families, returning citizens, veterans, youth — to benefits, job training, and community services through 29 specialized platforms covering workforce, health, housing, legal, youth services, and more, in 107 languages. (2) It connects organizations — nonprofits, workforce boards, health systems, government agencies — to each other through a referral loop, shared outcome data, and a grant intelligence engine that finds funding and tracks whether it was won. (3) It produces community-level evidence — Census-grounded, SDOH-scored, equity-framed — that organizations use to write grant proposals, advocate to funders and city councils, and measure whether their work is actually closing gaps.

**More concretely, the five daily-use capabilities:**

1. **AI Navigator (Nia/Malik):** A conversational AI for any resident — "I need childcare for my 2-year-old and I qualify for subsidy." The Navigator resolves the ZIP code, pulls live Census context, matches it against ThriveUp's benefits catalog, and gives a grounded answer with contact information. ChildCORE's provider data would make this answer far more accurate for childcare questions.

2. **Community Brief:** Any organization can enter a ZIP code or county and receive a one-page evidence document: demographics, poverty rate, health access gaps, housing burden, HDI score, and scenario projections for what happens if those gaps are closed. This is used in grant proposals and advocacy. The community brief currently has no childcare coverage or slot-gap section — ChildCORE's data would add that.

3. **Grant Discovery + Proposal Pipeline:** ThriveUp scans SAM.gov, Grants.gov, and USASpending daily, scores grants against the community's actual gaps, and surfaces the best matches. Organizations then build proposals inside ThriveUp using the community evidence. ChildCORE's slot-gap data would directly improve grant matching for childcare-related funding.

4. **Referral Loop:** CHWs (community health workers) submit referrals to partner organizations; the loop tracks whether the referral was accepted, served, and what outcome was achieved. This produces the outcome data that flows into grant compliance reports.

5. **Academy (Workforce Curriculum):** A free trade-skills curriculum (plumbing, HVAC, electrical, automotive) for adults who need credentialed workforce skills. Connects directly to local employer partners. This is where workforce-development grants and childcare access intersect — a parent can't complete a workforce program if they don't have childcare.

**The intersection with ChildCORE specifically:** The WSRCA (Workforce Solutions Rural Capital Area) in Central Texas — Williamson, Hays, Bastrop, Caldwell, Lee, Burnet, Llano, Blanco, and Milam counties — is already a named service area in ThriveUp's equity-loss engine (seeded as `RFP2026-004`, child care emphasis area). ChildCORE's data for those 9 counties would flow directly into that existing analysis without any new geographic scaffolding needed.
