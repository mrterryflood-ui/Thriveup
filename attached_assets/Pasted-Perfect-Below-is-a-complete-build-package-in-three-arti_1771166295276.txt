IGN-Thrive™ System Requirements Document (SRD)

⸻

1. System Overview

IGN-Thrive™ is a longitudinal, context-aware, structured autonomy system embedded within TxEA Empowerment Academy.

It integrates:
	•	Student simulation (Panther Village)
	•	Pathway governance
	•	Mentor pairing & tracking
	•	Executive function measurement
	•	GIS-layered contextual analytics
	•	Early warning & navigation workflows
	•	Alumni continuity

Core Principle

Every feature must support:
	1.	Autonomy
	2.	Guardrails
	3.	Navigation

If one is missing, feature is redesigned.

4. Revision Workflow Requirements
	1.	Student submits revision request.
	2.	System checks annual revision count.
	3.	Parent notification auto-sent.
	4.	Advisor receives request.
	5.	Revision justification rubric completed.
	6.	Advisor session required.
	7.	Plan edited collaboratively.
	8.	Version saved with timestamp.
	9.	Plan re-locked.

No silent changes permitted.

⸻

5. Early Warning Requirements

Flags triggered only when:
	•	Multi-domain decline OR
	•	Slope shift exceeds threshold OR
	•	Decision pattern risk clusters OR
	•	Context shock combined with protective factor deficit

All flags must generate:
	•	Explanation
	•	Assigned navigation action
	•	30-day measurable target

⸻

6. Security Requirements

	•	Role-based access
	•	Minimal necessary data collection
	•	Audit logs for all edits
	•	No raw address storage required
	•	Encrypted database
	•	Public dataset ingestion isolated from student DB

3. Thrive Domain Scoring

Domain A — Learning & Engagement (25%)

Score formula example:
	•	Attendance consistency: 30%
	•	Milestone completion: 30%
	•	Quest completion rate: 20%
	•	Portfolio update cadence: 20%

Domain A Score = weighted composite (0–100)

⸻

Domain B — Executive Function (20%)

Components:
	•	Reflection rubric average
	•	Revision justification quality
	•	Decision pattern stability index
	•	Recovery after loss behavior index

⸻

Domain C — Belonging (15%)

Components:
	•	Mentor meeting consistency
	•	House participation rate
	•	Peer collaboration logs
	•	Help-seeking behavior

⸻

Domain D — Wellbeing (10% if active)

Opt-in student check-ins.
If not active, weight redistributed proportionally.

⸻

Domain E — Context Load (15%)

Derived from GIS layer:
	•	SVI percentile
	•	Health burden composite
	•	Crime trend percentile
Normalized to 0–100 scale.

Note: This domain influences navigation urgency, not student penalty.

⸻

Domain F — Protective Factors (15%)
	•	Stable adult contact cadence
	•	Service participation
	•	Leadership engagement
	•	Portfolio momentum
	•	Club/activity anchors

⸻

4. Composite Thrive Formula

Thrive Score =
(0.25A + 0.20B + 0.15C + 0.10D + 0.15E + 0.15F)

Plus trend slope modifier (improving vs declining).

⸻

5. Flag Logic

Watch
	•	≥10% decline in one domain
	•	OR engagement drop >2 consecutive weeks

Support
	•	≥10% decline in two domains
	•	OR revision attempts ≥3 in one semester
	•	OR decision risk index > threshold

Stabilize
	•	≥15% decline in three domains
	•	OR declining slope across 60 days
	•	AND protective factor deficit

All thresholds configurable.

ARTIFACT 3

GIS Integration & Privacy Architecture Specification

⸻

1. Public Data Connectors

CDC PLACES
	•	API ingestion quarterly
	•	Variables selected for youth-relevant health proxies

CDC SVI
	•	Annual ingestion
	•	Tract + ZCTA compatible

FBI Crime Data API
	•	Quarterly ingestion
	•	Supplement with city open data where possible

⸻

2. Data Join Logic
	1.	Student Geography_Key stored.
	2.	Public datasets stored separately.
	3.	Join occurs via tract/ZCTA.
	4.	Only derived Context_Load_Index stored in student record.
	5.	Raw public data remains external.
