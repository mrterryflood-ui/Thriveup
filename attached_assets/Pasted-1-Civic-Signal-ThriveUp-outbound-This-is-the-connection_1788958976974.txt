1. Civic Signal → ThriveUp outbound

This is the connection currently returning 401 in the logs.

Item	Correct value
Credential	ThriveUp-issued opaque key stored as THRIVEUP_ISSUED_KEY
Header	x-ecosystem-key: <THRIVEUP_ISSUED_KEY>
Safe read probe	GET https://thrivingcommunitiesforall.com/api/chainweb/programs?topic=health&limit=1
Lesson push	POST https://thrivingcommunitiesforall.com/api/chainweb/webhook/civic-signal
RAG context	GET https://thrivingcommunitiesforall.com/api/chainweb/rag-context?...
POWER2PEOPLE_ISSUED_KEY should not be used for this connection.

The key remains an opaque ThriveUp-issued key; it is not a bearer token and should not be reformatted. The request should also send:

Accept: application/json
x-ecosystem-key: <THRIVEUP_ISSUED_KEY>
For POST requests:

Content-Type: application/json
One important current-code issue: Civic Signal presently prioritizes CIVIC_SIGNAL_ECOSYSTEM_KEY over THRIVEUP_ISSUED_KEY. Therefore, if both secrets exist, it may send the former even after THRIVEUP_ISSUED_KEY is corrected. The outbound client should use THRIVEUP_ISSUED_KEY as the authoritative ThriveUp-issued credential.

Also, Civic Signal currently treats /api/chainweb/rag-context as unauthenticated and sends no key. Current logs show that endpoint returning 401, so if ThriveUp now protects it, that call must also send x-ecosystem-key.

2. ThriveUp → Civic Signal lesson ingestion

Yes, the path remains:

POST /api/partner-exchange/v1/thriveup-lessons
But POWER2PEOPLE_ISSUED_KEY is retired. It cannot be reused or converted. The old key-only routes intentionally return 410.

This endpoint now requires a separately issued Partner Exchange v1 signed credential with scope:

thriveup-lessons:write
Every request requires all of these headers:

Authorization: Bearer <one-time-issued-v1-token>
X-Civic-Key-Id: <issued-key-id>
X-Civic-Timestamp: <ISO-8601-UTC-time>
X-Civic-Nonce: <new-UUID-for-every-attempt>
X-Civic-Partner-Origin: https://thrivingcommunitiesforall.com
X-Civic-Signature: <lowercase-hex-HMAC-SHA256>
Content-Type: application/json
The body must include:

{
  "contractVersion": "1.0"
}
The HMAC secret is the bearer token. Sign this newline-delimited canonical string:

timestamp
nonce
exact partner origin
uppercase HTTP method
path without query string
lowercase SHA-256 hex of stable JSON body
For lesson ingestion, the signed method and path are:

POST
/api/partner-exchange/v1/thriveup-lessons
The timestamp must be within five minutes, the nonce must be new, and the signed origin must exactly match the credential’s allowlist.

Bottom line

Outbound Civic Signal → ThriveUp: THRIVEUP_ISSUED_KEY in x-ecosystem-key.
Inbound ThriveUp → Civic Signal: newly issued v1 bearer/HMAC credential with six signed headers.
POWER2PEOPLE_ISSUED_KEY: retired; do not use it.
/api/partner-exchange/v1/thriveup-lessons: unchanged and correct for inbound lesson ingestion.
It is not the Civic Signal outbound webhook endpoint.
A clean inbound verification should return 201, contractVersion: "1.0", status: "accepted", and a trace ID. Do not place either credential value in chat, source control, or logs.
