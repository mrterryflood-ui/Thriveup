## 1. Structural gaps — the Replit dependency (fix these first; they break the "independent" claim)

Everything below reads Replit-only secrets, so the moment the platform is expected to run on owned/Vercel infrastructure it silently degrades to "not configured."

| # | What | Where (evidence) | Gap | Remediation |
|---|---|---|---|---|
| 1.1 | Email (Resend) | `server/email-service.ts` → `getResendClient()` reads `REPLIT_CONNECTORS_HOSTNAME` + `REPL_IDENTITY` / `WEB_REPL_RENEWAL` | Welcome email, Trade Sims digest, grant alerts, crisis escalation, stale-capacity reminders **all throw "Resend connector not available"** off Replit | Decouple: read a standalone `RESEND_API_KEY` env first; keep Replit connector as fallback. Verify each email type fires in production. **needs live check** |
| 1.2 | Sign-in / auth | `server/replit_integrations/auth/replitAuth.ts` + `storage.ts` | Auth is Replit OIDC; the "boot-stability OIDC repair" ≠ operational independent sign-in | Confirm replacement sign-in path works signed-out→signed-in; prove existing users' file access survives cutover. **needs live check** |
| 1.3 | File storage | `server/replit_integrations/object_storage/objectStorage.ts` | Uploads stored via Replit Object Storage | Prove existing files remain reachable on the owned-storage path before removing Replit. |
| 1.4 | Audio / image / chat / batch | `server/replit_integrations/{audio,image,chat,batch}/` | Media/voice/batch features tied to Replit Connectors | Map each to an owned provider or explicitly declare it Replit-only in the spec. |

These four are the "independent services cutover" that the plan's Phase 0 (lock the trunk) must resolve *before* the registry/navigation work, or we orchestrate a house of cards.

## Remediation order (measure twice, cut once)

1. **Lock + cutover (1.1–1.4)** — decouple email/auth/storage from Replit-only secrets; prove independent stack. Without this, everything else is pinned to Replit.
2. **Automations complete the loop (2.1–2.5)** — make digest/welcome/webhook/alerts actually deliver and *show* delivery.
3. **Cross-product exchanges (3.1–3.6)** — production smoke tests, then build the two net-new items (CVR ingest bridge, RPLICE exchange route).
4. **Routing cleanup (4.1–4.4)** — close the 502, merge directory PRs, audit mounted vs orphaned routes.
5. **Guides (5.1–5.2)** — per-page guide band + live automation status.

Each line above has a pass/fail verification gate; I will check against the *built output and live behavior*, not the code diff or the builder's self-report.
