What SAMHSA's forms-and-resources page contains — and what integrating it into RPLICE's intelligence engine looks like
What's actually on that page
The SAMHSA forms-and-resources page is a dense, structured collection organized into six functional clusters:
1. Budget & Financial Forms
SAMHSA Budget Template (PDF and accessible DOCX variants)
Budget Template User Guide + Key Features guide
Budget Review Checklist
Sample SF-424 / SF-424A forms (Match Required and Non-Match variants)
Budget Template Guidance
2. Application Guidance Documents
Formatting Requirements & System Validation rules
Developing Goals and Measurable Objectives (SMART objective framework)
Developing the Plan for Data Collection and Performance Measurement
Biographical Sketches and Position Descriptions guidance
3. Compliance & Policy Requirements
Intergovernmental Review (E.O. 12372) requirements
National Policy Requirements compendium
Block Grant SSP (Syringe Services Programs) funds guidance
Minority HIV/AIDS Initiative (MAI) SSP guidance
Participation Guidelines for Individuals with Lived Experience and Family
4. Performance Infrastructure
SPARS (SAMHSA's Performance Accountability and Reporting System — the mandatory post-award data portal)
GPRA (Government Performance and Results Act) measures — quarterly client-level data mandatory for all service grants
NOMs (National Outcome Measures) — CMHS-specific mental health outcome instruments
GPRA data collection tools (English and Spanish), CSV upload templates, codebooks, QxQ guides
5. Evidence Base Resources
Evidence-Based Practices Resource Center (EBPRC) — 60 guidelines/manuals, 14 toolkits, 16 advisories, 14 data reports, 4 screening/assessment tools
Cultural competency adapted practice framework
Community-Defined Evidence Practices (CDEPs) doctrine
National Network to Eliminate Disparities in Behavioral Health
6. Directory / Reference Infrastructure
Center for Behavioral Health Statistics and Quality (CBHSQ)
Directory of Single State Substance Abuse Agencies
Directory of Single State Mental Health Authorities
Implementation Science Pilot information (CCBHC and similar programs)
What the intelligence engine currently does with this territory
RPLICE already has:
A 12-hour scanner that queries samhsa.gov as one of its domains in the grants scan
A mock SAMHSA grant in the grant service (not real NOFO data)
NIH rack-and-stack scoring (not ported to SAMHSA)
IS frameworks (CFIR, RE-AIM, EPIS, ERIC) that are perfect mirrors of what SAMHSA requires
Measurement templates and SPARS-adjacent data collection concepts
A budget template concept in the grant pipeline pages
The gap is that none of these touch each other systematically. SAMHSA-specific intelligence isn't a first-class citizen — it's a sub-query in a generic scan. The forms and compliance requirements are not encoded as machine-readable logic. The IS frameworks RPLICE already owns are exactly what SAMHSA grades applications on, but the connection isn't wired.
What the integration looks like — layer by layer
Here is the architecture before a single line of code is written:
Layer 1 — SAMHSA Canonical Registry (shared/samhsa-registry.ts)
A new shared canonical file — parallel in structure to nih-funding-opportunities-registry.ts — that encodes:
The three SAMHSA grant centers and their program domains: CSAT (substance abuse treatment), CMHS (community mental health services), CSAP (substance abuse prevention)
Each center's mandatory performance system: CSAT → GPRA, CMHS → NOMs, CSAP → SPF/CORT
SAMHSA CFDA (Assistance Listing) numbers by program type — so any grant found on Grants.gov can be classified as SAMHSA and routed to the right evaluation logic
EBP requirement tiers: required, preferred, CDEP-eligible, IS pilot-eligible
Budget match requirements (some programs require 1:1 match; most do not)
The five-step Strategic Prevention Framework (SPF) — Assess, Plan, Implement, Evaluate, Sustain — as a named methodology parallel to CFIR/RE-AIM in is-catalog.ts
This file becomes the source of truth that all downstream services reference. It encodes "what SAMHSA cares about" in structured form.
Layer 2 — Enhanced Intelligence Scanner Domain (server/research-intelligence-scanner.ts)
Three new scan domains are added to the existing six:
samhsa_behavioral_health: Scans for SAMHSA EBPRC updates, new treatment advisories, recovery support program evidence, and behavioral health workforce developments. Connected to existing CFIR, RE-AIM, EPIS connectors.
samhsa_prevention: Scans for SPF program updates, CSAP grant forecasts, Strategic Prevention Framework pilots, and underage drinking/opioid prevention developments.
samhsa_implementation_science_pilots: Dedicated scan for IS pilot learnings — CCBHC updates, PIPBHC implementation outcomes, and NIMH IS partnership announcements. This is the highest-value domain because SAMHSA is actively building IS into its grant conditions.
The grants domain query is upgraded from generic federal scan to include explicit SAMHSA NOFO number extraction, center classification, and IS pilot eligibility flagging.
Layer 3 — SAMHSA Application Intelligence Service (server/samhsa-application-service.ts)
A new AI service — parallel in structure to wizard-ai-service.ts — that takes a NOFO number or description and returns structured application intelligence:
Output	What it does
Statement of Need draft	Uses SDOH data already in RPLICE's GIS loaders + CBHSQ statistics to build a jurisdiction-specific needs narrative with citations
EBP Selection Matrix	Queries the EBPRC structure (encoded in the registry) and recommends appropriate EBPs for the population and disorder type, with fidelity and adaptation notes
SMART Goals Generator	Aligned to SAMHSA's "Developing Goals and Measurable Objectives" guidance — not generic SMART goals, but ones that pass SAMHSA's review criteria
Data Collection Plan	Generates a Section D/E narrative pre-mapped to the correct SPARS/GPRA/NOMs instruments for the specific grant program — so the applicant knows what data they will collect quarterly before they apply
Budget Narrative Scaffolder	Structures the budget by SAMHSA object class categories (personnel, fringe, travel, equipment, supplies, contractual, other, indirect) with match/no-match logic
Attachment 12 Generator	For IS pilot-eligible grants, generates the implementation science participation statement
Organizational Capacity Narrative	Structures Section E based on the organization's existing data in RPLICE (stakeholders, past projects, capabilities)
This service is called by the grant pipeline UI and the AI assistant, not just the scanner.
Layer 4 — SAMHSA Grant Pipeline UI (new page client/src/pages/samhsa-grant-pipeline.tsx)
A dedicated SAMHSA-aware grant pipeline that differs from the R01/R03/SBIR pipelines:
NOFO Finder: Pulls live open NOFOs filtered by SAMHSA center, IS eligibility, population focus, and deadline window — real data via Grants.gov API, not mock data
Fit Scoring: Each NOFO is scored against the current project using the same rack-and-stack logic from nih-funding-opportunities-registry.ts, but extended with SAMHSA-specific signals: CFIR construct match, population overlap, EBP availability for the target condition
Section Builder: Step-by-step pipeline (Statement of Need → EBP Selection → Implementation Plan → Data Collection Plan → Budget → Attachments) where each section is AI-assisted by the application intelligence service
SPARS Readiness Check: A preflight that maps the proposed project's outcome measures to the specific GPRA/NOMs instruments that will be required post-award, so there are no surprises
IS Pilot Election Wizard: For eligible grants, a structured decision tree for whether to participate in the IS pilot, with the Attachment 12 auto-generated if elected
Layer 5 — SPARS/GPRA Performance Module (integrated into Measurement Studio)
The existing Measurement Studio already handles outcome measure design. This layer extends it with a SAMHSA compliance mode:
A new "SAMHSA SPARS mode" that maps the project's outcome measures to the mandatory GPRA/NOMs instruments for the specific grant program
Generates a data collection timeline (quarterly reporting windows) aligned to SPARS submission calendars
Creates the exportable data collection plan that becomes Section D/E of the project narrative
Post-award: tracks whether the project's actual data collection stays aligned to the approved plan
Layer 6 — SAMHSA EBPRC Connector (extends shared/is-catalog.ts)
The EBPRC has 60+ guidelines/manuals, 14 toolkits, 16 advisories. Rather than scraping it (which would go stale), the integration encodes:
The EBPRC's classification taxonomy: intervention type, population, disorder type, evidence tier
The cultural adaptation framework: what constitutes a systematic modification, how to document it for reviewers
The CDEP doctrine: when community-defined evidence practices are accepted, and what documentation SAMHSA requires
Linkage to RPLICE's existing BCT taxonomy and CFIR fidelity logic — because SAMHSA's fidelity monitoring requirements are exactly what the BCT fidelity logs already track
