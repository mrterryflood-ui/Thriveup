# Phase 4 — registry rail, geographic magnet map, disclosure

Environment: development workspace. No production repair, publish, repository pull, or push authorized by this phase.

## Before / Changed / Why

- County points came from estimated state offsets. All 3,144 development county rows differed from Census interior points; coordinates cannot be treated as observations merely because they are populated.
- Shared PageFrame now reads registry outcome, guide, upstream and downstream links. Access is the registry floor AND the legacy predicate. Home and shell-free embeds do not mount it; mobile defaults collapsed with an explicit session preference.
- MagnetMap uses the existing Leaflet organ, official county/ZCTA interior points, filing-ZIP organization aggregation, sourced SVI context and curated resource overlays. City gravity and statewide need are explicitly distinguished; county/MSA selections retain their scope. A county-extent control and accessible data list expose the same layers.
- Journey selection is identity-scoped and read-only: only this user's broad geography is returned. Explicit URL geography wins; failed/unsupported lookup does not substitute Austin.
- `/tools` initially exposes twelve destinations per group, retains complete search results, and provides expand/collapse controls. Existing public Operate-classified routes remain publicly reachable under “Other public tools”; operator controls are still staff-only.
- The county-FIPS-as-benefits-ZIP handoff is corrected. Generic poverty values are omitted from this new map because their legacy definitions can differ.

## Independent audit and reconciliation

Six read-only domains inspected changed surfaces: API contracts; runtime/DOM; UI/navigation; offline/storage; UX/performance; full-stack congruence.

Resolved: bounded resource SQL, normalized state selectors, stale cached geography suppression, explicit Central Texas default, phone link targets, accessible county/resource lists, conditional empty states, re-fitting changed coordinate sets, state/city scope disclosure, and poverty-definition ambiguity.

Reconciled: statewide county context is intentional, not a city-only measure; the UI labels it and offers an extent control. Public Operate-classified routes are not hidden, because that would break the existing public reachability contract; the public directory label is neutral.

Pre-existing/outside this phase: research fact writes can partially persist and a subsequent facts-read failure can report no storage. No research behavior was changed here. Owner: platform engineering; severity medium; review before relying on staff research retries as atomic.

## Limits / release state

- Full `directory-links` remains blocked by the separately documented third-party URLs. Its two external-link checks were skipped only in a temporary verification wrapper, not removed or weakened in the committed gate.
- County/ZCTA coordinate vintage is Census 2023. ZIP-primary-county relationships are approximate and omit unmatched organizations from county totals.
- Seeded curated pins do not establish independent location verification or current service availability. Proximity is a 1.5-degree bounding window, not routing distance.
- SVI vintage remains unavailable when absent from stored provenance. Legacy poverty values are not displayed in the new map.
- Saved-journey browser proof mocks the auth/context transport; the real anonymous endpoint is separately checked for 401. This is not a live OIDC sign-in test.
- Production centroid data has not been repaired or verified. User verification is required before push; publishing is a separate decision.
