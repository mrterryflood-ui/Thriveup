# ThriveUp — Complete System Inventory, Gap Map & Remediation Plan

**Purpose:** Answer one question with evidence instead of impressions: is this the complete, integrated, holistic system it is meant to be — the nonprofit for nonprofits and governments, where all the work gets done in one place, sustainably — and if not yet, what exactly remains, in what order, to close it.

**Method:** Every route in the platform was extracted from the route registry and assigned to a service domain. Nothing was sampled, nothing was summarized from memory. 374 classified routes (340 real pages + 34 redirect aliases) — all listed below.

**Coverage verdict in one line:** the inventory substantiates the holistic claim — every major domain of nonprofit and government work has live tooling, from foster care to mental health to grants to coalition operations to outcome receipts — and the remaining gaps are five specific, fixable seams, not missing domains.

---

## Part 0 — The system in numbers

- **374 classified routes** — 340 real pages, 34 redirect aliases (aliases consolidate old URLs; only one true duplicate-title pair remains).
- **Access distribution:** 306 public, 13 authenticated, 8 staff, 13 admin — the platform is open by default, governed where it must be.
- **18 service domains** (below), spanning: crisis response, survivors' services, behavioral health, foster care and child welfare, reentry and justice, veterans, rural and farm communities, benefits eligibility, education (a full gamified academy), workforce and income, family and household journeys, nonprofit program operations, grants and funding, partnership and coalition work, community evidence and intelligence, measurement and accountability, and platform operations.
- **External integrations (internal + external URLs that further the mission):** IRS records (Community Gravity), Census enrichment, HUD homelessness counts, official Texas solicitation sources, Civic Signal policy exchange, ChildCORE, STREETS, NSF TechAccess — plus an open partner integration surface: `/agency-connector`, `/api-docs`, `/widget-install`, `/for-partners` (embed our tools), `/for-nonprofits` (connect your data).

## Part 2 — The remaining 20%: five real gaps (evidence-based)

**Gap 1 — Journey continuity: the chain is linked conceptually, not yet contextually.**
Verified in code: only 4 of the 12 resident-journey routes accept a place parameter today (`/community-gravity`: place/zip/city/state; `/community-banks`: place; `/community-map`: geo/q; `/sdoh-explorer`: state). `/411`, `/benefits-screener`, `/parents`, the academy pages, `/community-analysis`, `/corridor-intelligence`, and `/chainweb` accept none. A family moving through the chain re-enters their place and context at each door. This is the single biggest distance between the story and the resident experience. **Fix: Part 3.**

**Gap 2 — Two sources of access truth.**
Five files still import the legacy sidebar's access predicate; visibility = registry AND legacy. It works, but it is coordination debt and a regression risk. **Fix: retire the legacy predicate, registry becomes the single access source.**

**Gap 3 — Domain gaps in the nonprofit-for-nonprofits mission (honest list).**
The inventory found five work domains with thin or absent coverage: volunteer management (scheduling and signup tracking), donor cultivation CRM (receipts exist; pipeline management is thin), constituent communications (email/SMS campaigns), financial and budget management, and full multilingual breadth. Each is a deliberate build-or-integrate decision — the `/agency-connector` exists precisely so partners can keep their incumbent systems and still join the chain. **Recommendation: integrate, don't build, for all five — sustainment over sprawl.**

**Gap 4 — Presentation grade vs utility grade.**
91 operate-lane routes and several specialist hubs are staff-utility grade, not stakeholder-grade; deep analytics tools are desktop-first; `/hub/legacy` still exists as a parallel front door. **Fix: naming/alias pass + polish the 12 stakeholder-visible routes.**

**Gap 5 — Measurement activation.**
The outcome machinery is built (outcome reporting, WIOA, longitudinal dashboards, donor receipts) but longitudinal impact accumulates only where communities adopt and use it. **Fix: activation is the roadmap's job (Part 5), not new code.**

## Part 3 — Context-preserved handoff across the resident journey (the design)

**The standard: one JourneyContext, carried in the URL, merged with the signed-in journey.**

- **JourneyContext = `{ place, audience, entry, referral? }`** — carried as URL query parameters (stateless, shareable, deep-linkable — the same pattern the outcome landings and demo door already use).
- **Merge rule:** explicit URL place always wins; otherwise the signed-in journey place (`use-magnet-journey-place`) fills in; otherwise the tool asks. No default city, ever.
- **Consent rules (per the Community Data Council principles):** place and audience are non-sensitive and carry freely across tools; household and referral context attach only when signed in AND consented.
- **Exit handoffs:** outbound external links carry source tags so partners can see the referral flow the platform generates for them.

**Handoff matrix — the 12 story-walk routes:**

| Route | Accepts today | Target state |
|---|---|---|
| `/411` | none | + place, audience |
| `/benefits-screener` | none | + place, audience |
| `/parents` | none | + place, audience |
| `/academy/financial-literacy` | none | + audience |
| `/academy/careers` | none | + audience |
| `/impact` | none | + place |
| `/community-analysis` | none | + place |
| `/corridor-intelligence` | none | + place |
| `/chainweb` | none | + place |
| `/community-gravity` | place, zip, city, state | + audience |
| `/community-banks` | place | complete |
| `/community-map` | geo, q | complete |

**Implementation:** one shared reader (`useJourneyContext`) and one writer (`buildJourneyHref(path, context)`) — small, additive, pattern already proven in this codebase. Phases: **A)** place handoff on the eight routes missing it; **B)** audience continuity; **C)** consent-gated household/referral context; **D)** external exit tagging.
