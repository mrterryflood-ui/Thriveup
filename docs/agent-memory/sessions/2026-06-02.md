## Navigator nationwide refactor (session end)

### What changed
- Replaced hardcoded Austin-only resource block in `NAVIGATOR_SYSTEM_PROMPT` with:
  - LOCATION INTELLIGENCE section (ask if missing, use context blocks)
  - NATIONAL RESOURCE FINDERS organized by category (housing, foster, health, legal, work)
  - INTERNAL TOOL LINKING TABLE (14 rows: need → /route)
- `assembleContext()` now:
  - Detects city names via regex and injects `[DETECTED LOCATION]` context
  - needKeywords: added `foster`, `reentry`, `immigration` categories
  - categoryMap: foster→youth, reentry→legal, immigration→legal
  - New PLATFORM RECOMMENDATION injections for foster, reentry, immigration

### Key decision
The Austin block was a patch. The real pattern is: (1) inject detected location as context, (2) AI uses [GIS DATA]/[AVAILABLE RESOURCES] blocks first, (3) fall back to national finders (211, findhelp.org, HRSA, etc.), (4) link internal tool when it matches the stated need. This scales to all 50 states without hardcoding.

### Known gap
Resource engine (`server/resource-engine.ts`) has only ~27 state-specific entries — mostly national fallbacks. Long-term: populate state-specific data for top 20 states. For now the national finders (211, findhelp.org) bridge the gap adequately.
