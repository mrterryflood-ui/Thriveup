## Navigator AI Fix — 2026-05-29 (late afternoon)

### Root cause identified and fixed

**Problem:** ThriveUp Navigator showing "I'm sorry, I'm having trouble connecting right now" on live deployed site (thrivingcommunitiesforall.com).

**Root cause (confirmed from deployment logs):**
```
[CollabAI-Stream] Launching 4 engines in parallel (RAG: 8 chunks)
[CollabAI] Gemini quota exhausted — skipping for 30 minutes
[CollabAI-Stream] Complete in 86907ms — 3-engine parallel synthesis
POST /api/navigator/chat 200 in 88044ms
```
Server returned **200 OK** but took **88 seconds**. Replit's deployment proxy has a ~60-second request timeout. The proxy closed the connection before the server finished; client's `catch` block fired the error message.

**Cause within cause:** `deepseek/deepseek-r1` is a chain-of-thought reasoning model. For a simple chat question ("Can you tell #DATA stories?") it ran its full thinking loop — 60-90 seconds is typical. The other two engines (Claude, OpenAI) finished in ~5s but the `Promise.all` waited for R1 to complete before synthesizing.

**Fixes applied to `server/collaborative-ai.ts`:**
1. **Per-engine timeout** — `callEngineWithTimeout()` wrapper using `Promise.race` with `ENGINE_TIMEOUT_MS = 15000`. Any engine that doesn't respond in 15 seconds is dropped from synthesis; others proceed immediately.
2. **Model switch** — `deepseek/deepseek-r1` → `deepseek/deepseek-chat` (DeepSeek V3). Same OpenRouter key, 10-20× faster (~3-5s typical), still high quality for conversational use. R1's chain-of-thought is inappropriate for a chat interface.
3. **Full engine error logging** — Previously only Gemini quota exhaustion was logged. Now all engine failures log to `console.error` so production logs surface any engine problem.
4. **`collaborativeStream` failure reporting** — Added `failedStreamEngines` logging parallel to what `collaborativeResponse` already had.

**Expected post-fix timing:** ~10-15s total (3 engines × ~5s each in parallel → synthesis → stream). Well within the 60s proxy timeout.

**No auth changes needed** — navigator is correctly behind `requireAuth`, user was authenticated.
