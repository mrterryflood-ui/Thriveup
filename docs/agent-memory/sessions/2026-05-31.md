# Session 2026-05-31

## Task 1: AI Chat Persistent Memory

### What was done
Wired full persistence for all three AI chat surfaces so conversations survive refresh and return visits.

### Navigator (`ai-navigator.tsx`)
- Backend DB persistence was already complete (`navigator_conversations` + `navigator_messages` tables, full `/api/navigator/*` routes in `server/navigator-routes.ts`)
- Gap: the component never re-loaded a prior session on open — every open started blank
- Fix: added a single `useEffect` placed **after** `startNewConversation` (must be after `loadConversation` useCallback or React throws "cannot access before initialization")
- Effect fires when `isOpen || mode === "page"`, `isAuthenticated`, `conversations` has results, `!activeConversationId`, and `messages.length === 0` → calls `loadConversation(conversations[0].id)`

### Sparky (`sparky-companion.tsx` + `routes.ts` + `schema.ts`)
- Two-tier persistence: DB (authenticated) + localStorage fallback (everyone)
- New schema tables: `sparky_sessions` + `sparky_session_messages`
- `npm run db:push` applied migration cleanly
- Routes added to `server/routes.ts`: modified `POST /api/sparky/chat`, added GET/DELETE CRUD
- Frontend: full rewrite with session state, history panel, auto-resume last session on mount

### AICompanion (`ai-companion.tsx`)
- localStorage only (component is embedded in lessons)
- `storageKey` = `spark_messages_${subject || "general"}_v1`

### Key gotcha
The Navigator auto-resume `useEffect` MUST be placed after `loadConversation` useCallback definition. Placing it before causes "Cannot access 'loadConversation' before initialization" runtime error.

## Task 3: Hub v2 — All 6 UX Improvements

### Changes

2. `hub-shell.tsx` — added `roles?: HubRole[]` to HubCardDef, `role` + `itiSurface/Prompt/Context/Tags` props, role filtering, ITI render at bottom

7. `App.tsx` — added /hub/connect route (aliases /hub/more)

### Key decisions
- Cards without `roles` field always show (safe default — no unintended hiding)
- Role stored in localStorage, not tied to auth — shadow workers / anonymous users fully supported
- ITI renders at the bottom of hub-shell's tool card section when itiSurface is provided — one prop, minimal invasiveness
- `tcaf_hub_onboarded` separate from `tcaf_hub_role` — allows "dismissed but no role" state
- clearRole() in useHubRole also clears onboarded flag → re-triggers onramp on next hub visit
