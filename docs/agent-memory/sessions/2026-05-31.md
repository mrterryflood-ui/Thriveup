# Session 2026-05-31

## Task 1: AI Chat Persistent Memory

### What was done
Wired full persistence for all three AI chat surfaces so conversations survive refresh and return visits.

### Navigator (`ai-navigator.tsx`)
- Backend DB persistence was already complete (`navigator_conversations` + `navigator_messages` tables, full `/api/navigator/*` routes in `server/navigator-routes.ts`)
- Gap: the component never re-loaded a prior session on open — every open started blank
- Fix: added a single `useEffect` placed **after** `startNewConversation` (must be after `loadConversation` useCallback or React throws "cannot access before initialization")
- Effect fires when `isOpen || mode === "page"`, `isAuthenticated`, `conversations` has results, `!activeConversationId`, and `messages.length === 0` → calls `loadConversation(conversations[0].id)`

### Sparky (`sparky-companion.tsx` + `routes.ts` + `schema.ts`)
- Two-tier persistence: DB (authenticated) + localStorage fallback (everyone)
- New schema tables: `sparky_sessions` + `sparky_session_messages`
- `npm run db:push` applied migration cleanly
- Routes added to `server/routes.ts`: modified `POST /api/sparky/chat`, added GET/DELETE CRUD
- Frontend: full rewrite with session state, history panel, auto-resume last session on mount

### AICompanion (`ai-companion.tsx`)
- localStorage only (component is embedded in lessons)
- `storageKey` = `spark_messages_${subject || "general"}_v1`

### Key gotcha
The Navigator auto-resume `useEffect` MUST be placed after `loadConversation` useCallback definition. Placing it before causes "Cannot access 'loadConversation' before initialization" runtime error.

## Task 2: Hub Navigation Redesign (All 4 Phases)

### Architecture
- New nav mode: "hub" (default) vs "classic" (sidebar, toggle button in header)
- Mode persisted in localStorage key `tcaf_nav_mode`

### New files created
- `client/src/lib/nav-mode.tsx` — NavModeProvider + useNavMode hook
- `client/src/components/bottom-tab-bar.tsx` — 5-tab persistent bottom bar (Home/Serve/Fund/Grow/More)
- `client/src/components/hub-shell.tsx` — reusable hub page shell (gradient header + filter chips + hero/tool card grid)
- `client/src/pages/hub-home.tsx` — Home hub (4 gateway cards + Quick Access row)
- `client/src/pages/hub-serve.tsx` — Serve hub (emerald, Benefits/Foster/Justice/Health filter chips)
- `client/src/pages/hub-fund.tsx` — Fund hub (amber, Opportunities/Writing/Applications/Analytics chips)
- `client/src/pages/hub-grow.tsx` — Grow hub (blue, Trade Sims/Workforce/Academy/AI chips)
- `client/src/pages/hub-more.tsx` — More hub (slate, Central Texas/Partners/Impact/About chips)
- `client/src/pages/workbench.tsx` — Split-pane composer (up to 4 pinned iframe panes, picker with tags)

### App.tsx changes
- Added NavModeProvider, useNavMode, BottomTabBar imports
- Added lazy imports for all 6 new pages
- Replaced AppLayout with: NavModeProvider → AppLayoutInner (new) → NavModeToggle (new)
- AppLayoutInner: detects iframe context (suppresses chrome for Workbench iframes), shows/hides sidebar + bottom tab bar based on mode
- Added 6 new routes: /hub, /hub/serve, /hub/fund, /hub/grow, /hub/more, /workbench

### Key design decisions
- Tailwind color map in hub-shell.tsx ensures JIT doesn't tree-shake color classes
- `authOnly: true` cards hidden for unauthenticated users at filter time (not rendered at all)
- Iframe detection: `window.self !== window.top` in useState initializer — if in iframe, renders only content (no header/sidebar/tab bar)
- Bottom tab bar: 60px height, `pb-[60px]` on main content wrapper

### Hub color palette
- Home: violet/purple gradient
- Serve: emerald/teal/green gradient
- Fund: amber/orange gradient
- Grow: blue/indigo gradient
- More: slate gradient
- Workbench: indigo/violet gradient

### Workbench (P4)

- Pick up to 4 → renders as iframe grid (2-col or 1-col layout toggle)
