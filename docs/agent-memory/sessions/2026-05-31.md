# Session 2026-05-31

## Task: AI Chat Persistent Memory

### What was done
Wired full persistence for all three AI chat surfaces so conversations survive refresh and return visits.

### Navigator (`ai-navigator.tsx`)
- Backend DB persistence was already complete (`navigator_conversations` + `navigator_messages` tables, full `/api/navigator/*` routes in `server/navigator-routes.ts`)
- Gap: the component never re-loaded a prior session on open — every open started blank
- Fix: added a single `useEffect` placed **after** `startNewConversation` (must be after `loadConversation` useCallback or React throws "cannot access before initialization")
- Effect fires when `isOpen || mode === "page"`, `isAuthenticated`, `conversations` has results, `!activeConversationId`, and `messages.length === 0` → calls `loadConversation(conversations[0].id)`

### Sparky (`sparky-companion.tsx`)
- Two-tier persistence: DB (authenticated) + localStorage fallback (everyone)
- New schema tables: `sparky_sessions` + `sparky_session_messages` (appended to `shared/schema.ts`)
- `npm run db:push` applied migration cleanly
- Routes added to `server/routes.ts`:
  - Modified `POST /api/sparky/chat`: extracts `sessionId`, creates/verifies session, saves user message before stream, accumulates `fullResponseText` in `onChunk`, fire-and-forgets assistant message save in `onDone`
  - `GET /api/sparky/sessions` — list sessions for user
  - `GET /api/sparky/sessions/:id/messages` — load session messages
  - `DELETE /api/sparky/sessions/:id` — delete session + its messages
- Frontend: full rewrite with session state, `useQuery` for sessions, history panel (toggle via History icon), auto-resume last session on mount, localStorage save after every exchange, localStorage restore when not authenticated
- Privacy notice updated to reflect saving

### AICompanion (`ai-companion.tsx`)
- localStorage only (component is embedded in lessons, no user-scoped DB needed)
- `storageKey` = `spark_messages_${subject || "general"}_v1`
- Restore on mount, save on messages change, clear on clearChat

### Key gotcha
The Navigator auto-resume `useEffect` MUST be placed after `loadConversation` useCallback definition, not before it. Placing it before caused "Cannot access 'loadConversation' before initialization" runtime error.

### Schema type name
Used `SparkySessionRow` (not `SparkySession`) to avoid clash with the frontend interface named `SparkySessionInfo`.
