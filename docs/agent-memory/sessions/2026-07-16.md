
## Knowledge Graph — built and connected (2026-07-16)

### What was built
- `shared/schema.ts` — added `kg_nodes` (id, type, label, description, url, properties, source) + `kg_edges` (from/to/relationship/weight/properties/source) tables with FK cascade
- `server/knowledge-graph.ts` — core service: upsertNode, upsertEdge, getNode, getNeighbors (BFS recursive CTE), searchNodes, listNodes, getStats, buildGraphContext, buildEcosystemGraphSummary, seedKnowledgeGraph (idempotent, two-phase: nodes first then edges)
- `server/knowledge-graph-routes.ts` — REST + ecosystem endpoints (see below)
- `server/ai-provider.ts` — `withEthicalPreamble()` now appends graph context (via AsyncLocalStorage) alongside community context
- `server/routes.ts` — registers KG routes + calls seedKnowledgeGraph() on startup

### API endpoints
- `GET /api/knowledge-graph/stats` — counts by type
- `GET /api/knowledge-graph/nodes?type=&q=&limit=` — list/search
- `GET /api/knowledge-graph/nodes/:id` — single node
- `GET /api/knowledge-graph/neighbors/:id?depth=1|2|3` — BFS neighborhood
- `GET /api/knowledge-graph/context/:id` — AI-injectable text block
- `POST /api/knowledge-graph/nodes` — upsert [auth]
- `POST /api/knowledge-graph/edges` — add edge [auth]
- `DELETE /api/knowledge-graph/nodes/:id` — delete + cascade [auth]
- `GET /api/ecosystem/knowledge-graph/nodes` — scoped view [x-ecosystem-key]
- `GET /api/ecosystem/knowledge-graph/neighbors/:id` — BFS [x-ecosystem-key]
- `GET /api/ecosystem/knowledge-graph/context/:id` — AI block [x-ecosystem-key]
- `POST /api/ecosystem/knowledge-graph/nodes` — contribute node [x-ecosystem-key]
- `POST /api/ecosystem/knowledge-graph/edges` — contribute edge [x-ecosystem-key]

### Key lesson
Seeder must be two-phase: upsert all nodes → then all edges. Mixing them in a single batch causes FK violations (edge references node not yet committed in same batch).
