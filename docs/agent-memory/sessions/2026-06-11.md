### I01 — HIGH FIXED: Duplicate React key "ALL" in BenefitsCommandCenter
- Root cause: `countyData.map(d => ({type: d.benefitType, ...}))` in `/api/benefits/command-center/stats` — when DB has multiple rows for same county+benefitType (e.g. two rows with benefitType="ALL"), the client-side `key={b.type}` fired a React duplicate key warning
- Fixed: server/benefits-routes.ts line 509 — replaced `.map()` with `Array.from(new Map(countyData.map(d => [d.benefitType, {...}])).values())` to deduplicate by benefitType before sending to client
- Verified: after server restart, Benefits Command Center console shows NO duplicate key warning

### I02 — IDENTIFIED (dev-only, no action needed): Universal 400 on every page

- Conclusion: Vite dev server responding to a browser-level prefetch/ping request (not an Express route)
- Dev-only artifact; won't appear on deployed production URL
- favicon.ico, manifest.json, robots.txt all return 200

### I03 — MOD FIXED: Game routes missing Zod validation
