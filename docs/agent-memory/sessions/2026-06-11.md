## Navigator PDF loader fix

### Root causes (two separate bugs)
1. **Auth wall:** `/api/navigator/extract-text` had `requireAuth` middleware — the paperclip button is visible to logged-out users but the endpoint rejected them with 401.
2. **Broken pdf-parse v2:** The route used `(await import("pdf-parse")).default` which is `undefined` in `pdf-parse@2.4.5` — v2 completely changed its API (exports `PDFParse` class, requires a URL not a buffer).

### Fix
- Removed `requireAuth` from `/api/navigator/extract-text` (stateless endpoint, no PII stored, no security reason to gate it).
- Replaced `pdf-parse` call with `pdfBufferToText()` imported from `rfp-ingestion.ts` — uses `pdftotext` CLI which is installed and proven.

### Lesson
`pdf-parse@2.x` is a completely different package from v1. Any v1 code (`pdf(buffer).then(d => d.text)`) will silently get `undefined` and throw. Use `pdfBufferToText` from `rfp-ingestion.ts` for all PDF-to-text needs in this codebase.
