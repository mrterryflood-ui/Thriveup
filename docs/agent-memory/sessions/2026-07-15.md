## Key Lessons Learned
- L1: "Missing backend route" scan using client-side URL strings vs server route files misses parameterized routes (`:id` matches literal "demo"). Always search server files for matching parameterized patterns, not just exact string matches.
- L2: `/api/case-manager/demo/risk-chain` is handled by `/api/case-manager/:id/risk-chain` in `resident-journey.ts` — "demo" is a valid participant ID that triggers `ensureDemoScenario()`.
- L3: The ecosystem platform-directives route requires `requireEcosystemAuth` (machine-to-machine key). Internal ThriveUp pages that display this data need the new `GET /api/ecosystem/internal/platform-directives/:platformId` route (requireAuth).
- L4: `handleInterventions` is a named function used as route handler — try/catch scanner counting "routes without try/catch" misses this pattern. The scanner counts `app.get(...)` calls; if the handler is a named function that internally has try/catch, the scanner flags it as missing.
