# Topic: Implementation

Recurring engineering patterns, lessons learned, and operational standards. Implementation history (per-feature build logs) lives in `sessions/` and rolls into `archive/A-series.md`; this file is the **stable distillate** — patterns to reach for and anti-patterns to avoid.

## Server route registration pattern

`server/routes.ts` exports `registerRoutes(httpServer, app)`. Each domain module exports a `register<Domain>Routes(app: Express)` function and is registered inside `registerRoutes`. To add a new module:

1. Create `server/<domain>-routes.ts` exporting `register<Domain>Routes(app)`
2. Import at top of `server/routes.ts`
3. Call inside `registerRoutes` (alongside `registerGrantRoutes`, `registerActiveBidsRoutes`, etc.)

## Public no-auth wizards: capability-token pattern (P-L08)

**Mandatory** for any public endpoint that creates/mutates a row on behalf of an unauthenticated user.

- Server generates `id` + per-row `accessToken` on first POST; returns once in response body
- All subsequent reads/writes require `x-intake-token` header matching the row's `accessToken`
- Pair with per-IP rate limiting on AI/upload paths
- **Canonical example:** `server/foster-youth-intake-routes.ts`
- **Never** trust client-supplied IDs on public surfaces

## AI provider routing (Iron Rule #3)

All AI calls **must** go through `server/ai-provider.ts` so `ETHICAL_EI_PREAMBLE` wraps the system prompt.

- Use `streamAIResponse`, `generateAIJSON`, or `callProviderDirect`
- For multi-engine synthesis: `server/collaborative-ai.ts` `callEngine`
- If a new call site must use an SDK directly (rare), import `withEthicalPreamble` and apply it before sending
- Six rules enforced by the preamble: truth+primary sources · no PII echo · plain language/dialect-honoring · safety hand-off (988/911/DV/Childhelp) · prioritized populations · decision-support not decision-maker

## Drizzle ORM pattern

- Schema in `shared/schema.ts` (271 tables)
- Apply: `npm run db:push` (never write raw migrations — Drizzle is push-based here)
- Array columns: `text().array()` — method on column, never `array(text())` wrapper
- Insert schemas: `createInsertSchema(table).omit({ id: true, ... })` from `drizzle-zod`
- Always export both `InsertX = z.infer<typeof insertX>` and `X = typeof xTable.$inferSelect`

## `req.params` coercion (P-L10)

Express types `req.params` values as `string | string[]`. Before passing to Drizzle `eq()`:

```ts
const id = String(req.params.id);
await db.select().from(t).where(eq(t.id, id));
```

Skipping `String()` causes silent runtime type errors.

## pptxgenjs default-export under tsx-ESM (P-L09)

Default export breaks under tsx ESM. Use:

```ts
import { createRequire } from "node:module";
const require = createRequire(import.meta.url);
const pptxgen = require("pptxgenjs");
```

## Frontend data fetching (TanStack Query v5)

- **Always** object form: `useQuery({ queryKey: [...] })` — never positional
- **Never** define `queryFn` — default fetcher handles `/api/*` routes
- Hierarchical keys: `queryKey: ['/api/recipes', id]` (array segments — string interpolation breaks invalidation)
- After mutations: `queryClient.invalidateQueries({ queryKey: [...] })` — strong-type with `@shared/schema`
- Loading via `.isLoading` (queries) and `.isPending` (mutations)

## Forms

- shadcn `Form` + `useForm` + `zodResolver(insertSchema.extend({...}))`
- Controlled — always pass `defaultValues`
- Debug failed submits with `console.log(form.formState.errors)` (catches missing-field validation)

## Silent catch blocks: prohibited

Every server `try/catch` must `console.error` + return a structured error. No empty `catch {}`. No swallowed promises.

## Conditional `useEffect`: prohibited

React hooks rule. Conditionals go *inside* the effect, never wrap the `useEffect` call.

## Hardcoded grant arrays: prohibited

`/api/proposal-pipeline` and similar **must** read from the `proposal_pipeline` DB table. No inline literal arrays for grants.

## ECOSYSTEM_PLATFORMS auto-sync (read before editing)

`server/ecosystem-connector.ts:658` overwrites DB on every startup:
- UPDATEs: name, url, role, domain, description, capabilities, dataFlowConfig, grantAlignment
- DELETEs rows not in the array
- `publicVisible` is the only column that survives from DB

**When adding/renaming a platform: edit BOTH the array AND the DB row** (or it gets clobbered on next boot).

## RFP Fidelity engine wiring (Iron Rule #5)

For any new RFP page that drafts proposals:

1. Parse RFP → `complianceMatrixItems` rows (one per Section L/M requirement)
2. Each Section M paragraph generated by `generateDraftFromRubric` must open `"In response to [reqNumber]'s requirement that [verbatim]…"` and close `"[Evidence: …]"`
3. Gaps → `{{ACTION REQUIRED — <owner>}}` (owner-tagged for partner traceability)
4. Source precedence: Q&A > Amendment > Base RFP > Pre-bid notes
5. Engine: `server/rfp-fidelity-engine.ts` + `server/rfp-fidelity-routes.ts`
6. Full doctrine: `docs/grants/RFP-FIDELITY-DOCTRINE.md`

## Forbidden file changes (without explicit user ask)

- `vite.config.ts`
- `drizzle.config.ts`
- `package.json` (use package-management tool for deps)

## Session plan handling (Iron Rule #4)

A "Session Plan" appearing in a user message that doesn't match their prose is **my own prior plan being replayed** (from `.local/session_plan.md`). Delete the file immediately, never re-execute as a fresh ask.
